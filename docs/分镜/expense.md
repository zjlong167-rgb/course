# 报销审批流程分镜（EX-01，2026-11-13）

目标：跟随一张报销单理解各角色职责、分支原因与付款完成边界。替代 S01 三步最小演示；仍是作者预设路径，无学员自主决策。教学金额、授权额度及规则并非通用财务制度，待作者正式批准。

样例：`samples/valid/expense.json`；可复现编排源：`scripts/upgrade-expense.mjs`。v1 / flow@1.0.0，1120×660，三个独立场景；所有动作通过共享播放器重建，不添加课程专属时钟。

| 场景 | 步骤 | 时长 | 关键画面 |
| --- | --- | --- | --- |
| 正常报销 · 材料齐全 | 整理材料 → 提交主管 → 主管通过 → 财务核验 → 出纳付款 → 到账归档 | 6×3500ms＝21秒 | ¥800 单据沿主线移动；最后一步前仍为付款中 |
| 退回补正 · 缺少附件 | 前三步相同 → 财务退回 → 补齐重提 → 主管重新确认 → 财务再次核验 → 出纳付款 → 到账归档 | 9×3500ms＝31.5秒 | 单据进入下方补正支线再回申请人，退回时出纳未激活 |
| 超额加签 · 授权审批 | 整理材料 → 提交主管 → 判断额度 → 负责人加签 → 财务核验 → 出纳付款 → 到账归档 | 7×3500ms＝24.5秒 | ¥5800 超出示例 ¥3000 额度，经上方负责人后交财务 |

对象：7 个角色/环节 node，1 个流转单据 packet（无 TCP 字段），8 条有向 edge。单据位于角色上方；加签、补正分别位于主线上下。对象详情记录职责，连线记录路径及说明；所有场景都保留全图作为路径对照。

每步在 0ms 清理上一高亮并更新当前角色、连线和单据状态；切换角色时前一角色标记已处理。250ms 开始移动单据，1500ms 到达，剩余时间阅读讲解。付款处理中不设置 paid，确认成功归档步骤才设 paid，界面显示已支付。

验收：每场景任意跳转、回退和重复定位得到相同对象状态；切场景暂停并从 0ms 开始；模板 ID 重映射后路径可解析；桌面与小屏（可横向滑动画布）控制、讲解、选择详情一致。证据见《报销流程优化验收》。
